    API reference¶

    This page lists every public class and argument, what each one does, and where it stops. For task-oriented explanations, start with the user guide: Choosing a route.

    The top-level package exports GAM, FitControl, EFSControl, OperatorControl, ContinuousDiscretizationControl, EFSOptimizerDiagnostics, GAMResults, GAMInferenceResult, GAMPredictionResult and GAMPredictor. Row sources and DiscretizationBudget come from jaxgam.data, families from jaxgam.families and links from jaxgam.links.

    Setup for the examples on this page

    The examples run in order in one Python process. The block below defines the data they share: a data frame data with 600 rows, a row source source over it with response y, a second row source count_source with the count response count, and a small newdata frame. The grouping factor g has 300 levels with two rows each; f is a factor with three levels.

    import numpy as np
import pandas as pd

from jaxgam import GAM, FitControl
from jaxgam.data import DataFrameRowSource

rng = np.random.default_rng(1)
n = 600
levels = [f"g{i:03d}" for i in range(300)]
x = rng.uniform(0, 1, n)
z = rng.uniform(0, 1, n)
g = pd.Categorical(np.repeat(levels, 2), categories=levels)
group_effect = rng.normal(0, 0.5, len(levels))
data = pd.DataFrame(
    {
        "x": x,
        "z": z,
        "g": g,
        "f": pd.Categorical(rng.choice(["a", "b", "c"], n)),
        "y": np.sin(2 * np.pi * x) + 0.5 * z + rng.normal(0, 0.3, n),
        "count": rng.poisson(np.exp(0.3 + 0.5 * x + group_effect[g.codes])).astype(
            float
        ),
    }
)
source = DataFrameRowSource(data, response="y")
count_source = DataFrameRowSource(data, response="count")
newdata = pd.DataFrame(
    {
        "x": np.linspace(0.05, 0.95, 5),
        "z": 0.5,
        "g": pd.Categorical(["g000"] * 5, categories=levels),
        "f": pd.Categorical(["a"] * 5, categories=["a", "b", "c"]),
    }
)

    GAM¶

    GAM holds a model specification. GAM.fit() fits it and returns a frozen result object.

    model = GAM("y ~ s(x) + s(z)", family="gaussian")
fit = model.fit(data)  # result="full" is the default
print(fit.converged, fit.execution_route, fit.lambda_strategy)

    True dense newton_reml

    Constructor¶

    GAM(formula, family="gaussian", method="REML", sp=None, control=None, **kwargs)

    Argument Default What it does
    formula required Model formula, for example "y ~ s(x) + z". See Formula syntax. The formula is parsed in fit(), not in the constructor.
    family "gaussian" A family name ("gaussian", "binomial", "poisson", "gamma", "nb") or a family instance. A name always gives the default link; pass an instance such as Gamma(link="log") for another link. An unknown name raises KeyError in fit(). See Families.
    method "REML" Smoothing parameter criterion. Only "REML" is accepted (case-insensitive). "ML" raises NotImplementedError; any other value raises ValueError.
    sp None Fixed smoothing parameters: one positive, finite value per penalty, on the natural scale. When given, smoothing parameters are not estimated. A wrong length or a non-positive value raises ValueError in fit(). fit.smoothing_params reports the values you supplied.
    control None A FitControl. None means FitControl(), the dense route. Anything else raises TypeError("control must be a FitControl instance or None.").

    **kwargs accepts only these keywords. Any other keyword raises TypeError.

    Keyword Accepted values What it does
    optimizer "newton" (default), "efs" "efs" selects the Fellner-Schall optimizer when smoothing parameters are estimated. Another string raises NotImplementedError; a non-string raises ValueError.
    device None (default), "cpu", "gpu" Where the fit runs. None leaves placement to JAX's default device. "gpu" raises RuntimeError in fit() when JAX has no GPU backend. Another value raises ValueError. The operator route accepts only None or "cpu".
    backend None, "jax" Anything else raises NotImplementedError.
    select False True (shrinkage selection) raises NotImplementedError.
    gamma 1.0 Any other value raises NotImplementedError.
    knots None User-supplied knots raise NotImplementedError.

    fit¶

    fit(data, weights=None, offset=None, *, result="full")

    Argument What it does
    data A pandas DataFrame or a dict of columns on the dense route. A row source on the streamed, discretized and operator routes.
    weights Prior weights, shape (n,). Dense route only.
    offset Offset added to the linear predictor, shape (n,). Dense route only.
    result "full", "inference" or "prediction". Anything else raises ValueError.

    The three result modes:

    result= Returns Routes Keeps
    "full" (default) GAMResults dense Everything: training design, fitted values, Vp, per-smooth EDF, summary(), plot()
    "inference" GAMInferenceResult dense Coefficients, Vp, per-smooth EDF and fit diagnostics; no training arrays
    "prediction" GAMPredictionResult all four Coefficients and scalar diagnostics; standard errors only if FitControl.uncertainty asks for them

    What each route takes as data:

    Route FitControl(execution=...) data Weights and offset result
    Dense "dense" (default) DataFrame or dict. A row source raises TypeError. fit(weights=, offset=) any of the three
    Streamed "stream" Row source. A DataFrame raises TypeError. Owned by the row source. Passing weights= or offset= to fit() raises ValueError. "prediction" only. Any other value raises NotImplementedError.
    Discretized "discrete" Row source Owned by the row source "prediction" only
    Operator "operator" Row source Owned by the row source "prediction" only

    Because fit() defaults to result="full", a fit on the streamed, discretized or operator route must pass result="prediction".

    Fit control¶

    All five control classes are frozen dataclasses. Each checks its own fields when constructed and raises ValueError (or TypeError where noted) with the message quoted below. Integer fields must be Python int values: a NumPy integer is rejected, except in OperatorControl. Combinations that depend on the model or the data are checked in GAM.fit(); the route sections under Fitting routes list them.

    from jaxgam import ContinuousDiscretizationControl, EFSControl, OperatorControl
from jaxgam.data import DiscretizationBudget

control = FitControl(
    execution="discrete",
    discretization=ContinuousDiscretizationControl(
        m=50, budget=DiscretizationBudget(max_table_bytes=128 * 1024 * 1024)
    ),
    smoothing_strategy="working_model_reml",
)
print(control.execution, control.discretization.m)

    discrete 50

    FitControl¶

    FitControl chooses the route, the linear solver, the memory budgets and what a prediction result keeps for standard errors.

    Field Default Read by What it does
    execution "dense" all The route: "dense", "stream", "discrete" or "operator".
    batch_rows 65_536 streamed, discretized, operator; prediction results Rows requested per row-source scan. Streamed setup scans use fewer rows when needed to fit memory_budget_bytes, and the operator fit uses the source's row count when that is smaller. Also the default batch of GAMPredictionResult.predict_iter() and the scan size of bulk_link_variance(). The dense fit does not read it.
    memory_budget_bytes 512 * 1024 * 1024 streamed, discretized, operator; prediction results Upper bound on the known arrays of the setup pass and the fit. A fit whose planned workspace exceeds it raises MemoryError before allocating. On every route it also bounds Vp and per-call prediction workspace of a prediction result. The dense fit itself is not budgeted.
    output_budget_bytes 512 * 1024 * 1024 prediction results Largest output one predict() or predict_matrix() call on a prediction result may return; each predict_iter() batch is one call.
    uncertainty "none" prediction results What a prediction result keeps for standard errors: "none" (nothing; predict(se_fit=True) raises RuntimeError), "fisher" (a factor of the penalized Fisher system), "covariance" (the dense Vp as well, checked against memory_budget_bytes). The operator route accepts only "none". Full and inference results always keep Vp.
    linear_solver "cholesky" all "cholesky", "qr" or "pcg". Dense and discretized take "cholesky"; streamed takes "cholesky" or "qr"; operator requires "pcg".
    gaussian_compression False dense, streamed Requests Gaussian QR compression. Must be a Python bool.
    efs EFSControl() dense, streamed, operator Limits of the Fellner-Schall optimizer.
    operator OperatorControl() operator Limits of the operator fit.
    discretization None discretized The discretization policy. Required when execution="discrete", refused otherwise.
    smoothing_strategy "exact_reml" discretized "working_model_reml" selects smoothing parameters on the discretized route. The discretized route cannot estimate them with "exact_reml".
    working_model_max_iterations 200 discretized Iteration limit of the discretized fit, except a Gaussian identity fit with fixed sp. Reaching it gives a RuntimeWarning and converged=False.
    working_model_epsilon 1e-7 discretized Convergence threshold on the relative change in penalized deviance (and in the log scale, when the scale is estimated).

    Checks at construction, in order:

    1. execution not one of the four: "execution must be 'dense', 'stream', 'operator', or 'discrete'."
    2. batch_rows, memory_budget_bytes or output_budget_bytes not a positive int: "{name} must be a positive integer."
    3. "uncertainty must be 'none', 'fisher', or 'covariance'."
    4. "linear_solver must be 'cholesky', 'qr', or 'pcg'."
    5. "Unsupported smoothing_strategy."
    6. smoothing_strategy="working_model_reml" with another route: "working_model_reml requires execution='discrete'."
    7. "working_model_max_iterations must be a positive integer."
    8. "working_model_epsilon must be positive and finite."
    9. "gaussian_compression must be a boolean."
    10. "operator must be an OperatorControl instance." and "efs must be an EFSControl instance."
    11. TypeError: "discretization must be a ContinuousDiscretizationControl or None."
    12. execution="discrete" without a policy: "execution='discrete' requires an explicit discretization policy."
    13. A policy with another route: "A discretization policy requires execution='discrete'."

    Only rules 6, 12 and 13 combine fields. A solver that does not suit the route, uncertainty on the operator route, or gaussian_compression on a route that ignores it all construct without error and are handled in GAM.fit().

    FitControl(execution: Literal['dense', 'stream', 'operator', 'discrete'] = 'dense', batch_rows: int = 65536, memory_budget_bytes: int = 512 * 1024 * 1024, output_budget_bytes: int = 512 * 1024 * 1024, uncertainty: Literal['none', 'fisher', 'covariance'] = 'none', linear_solver: Literal['cholesky', 'qr', 'pcg'] = 'cholesky', gaussian_compression: bool = False, efs: EFSControl = EFSControl(), operator: OperatorControl = OperatorControl(), discretization: ContinuousDiscretizationControl | None = None, smoothing_strategy: Literal['exact_reml', 'working_model_reml'] = 'exact_reml', working_model_max_iterations: int = 200, working_model_epsilon: float = 1e-07) dataclass ¶

    Execution route and explicit resource policy for a fit.

    execution selects the route; the other fields set batching, memory budgets and what a prediction result retains.

    uncertainty='none' is deliberately the default for prediction-only results. It retains no covariance. 'fisher' retains a triangular factor (a Cholesky factor, or a pivoted QR factor on the QR-solver routes) for exact requested-row standard errors; 'covariance' also materializes the public dense covariance, subject to memory_budget_bytes.

    The dense fitting backend is not memory-budgeted: these limits apply to prediction matrices/SE workspace and explicit covariance materialization. The streamed backend additionally rejects known live PIRLS workspaces (coefficient reductions plus one design batch) above memory_budget_bytes. Phase-1 streamed preparation scans at most batch_rows rows at a time and shrinks that size until its prospective setup workspace (JaxGAM-owned arrays plus the exact-knot SQLite scope) fits memory_budget_bytes; a budget too small for one row is rejected before any full-data scan. When the budget also holds them at that size, exact cubic knots are found from covariate columns gathered in memory (8 bytes per row per column, as many columns per scan as fit) instead of the row-count-independent SQLite scan; the knots are identical either way. Source-owned storage and allocator overhead remain outside these bounds. Gaussian QR adds a route-specific ledger for its merge buffers and compact score/derivative arrays, including either the small-penalty Newton Hessian or the bounded large-penalty L-BFGS-B work arrays. Native LAPACK/XLA workspace is not an allocator hard cap.

    gaussian_compression=True opts a Gaussian identity-link fit into one weighted QR reduction followed by coefficient-space REML trials. With execution='stream' the reduction consumes one bounded replay after prepared setup and retains no training rows. The initial route requires finite weights in the PIRLS unclipped interval and a full identifiable coefficient map. Ineligible dense models use the ordinary dense route and report the reason in execution_fallback_reason.

    execution='discrete' fits mgcv's compact discretized design (bam(discrete=TRUE)) from a replayable source under the explicit discretization policy. It combines retained compact setup, indexed action, and solver workspaces in a conservative fit peak; its Phase-1 construction allocations are separately bounded by the discretization policy. The discrete route owns its solves, so linear_solver='qr' is rejected there, and a gaussian_compression request is reported unmet in execution_fallback_reason.

    smoothing_strategy='working_model_reml' (discrete only) selects the smoothing parameters by pinned mgcv bam(discrete=TRUE)'s performance iteration (bgam.fitd): one limited Sl.fitChol Newton proposal on each iteration's working model, stopped when the penalized deviance (and an estimated log scale) changes by less than working_model_epsilon within working_model_max_iterations. Gaussian identity models use one frozen working model; Poisson, Binomial and Gamma re-form a Fisher working model (IRLS weights, no observed-curvature split) at every iteration, with the scale fixed at one or, for Gamma, estimated. The negative binomial uses bgam.fitd's dDeta Newton working model and, when theta is estimated, re-estimates it each iteration by estimate.theta at the current mean. This is not the nested exact REML optimization of the dense route. An explicit sp instead runs the same iteration with every smoothing parameter fixed.

    EFSControl¶

    EFSControl sets the limits of the Fellner-Schall optimizer. It is read only when optimizer="efs" and sp is None, on the dense, streamed and operator routes. The discretized route never reads it.

    Field Default Read by What it does
    outer_limit 200 dense, streamed, operator Maximum outer iterations. A stop first met on the last allowed iteration is reported as an iteration limit, not as converged.
    log_lambda_max 15.0 dense, streamed, operator Cap on trial log smoothing parameters.
    score_tolerance 0.1 dense, streamed, operator Score-window stop: after iteration 3, the largest proposed log smoothing parameter step is below 0.05 and the last four scores change by less than this.
    pirls_tolerance 1e-7 dense, streamed, operator Inner fit tolerance on dense and streamed; on all three, the deviance-change stop abs(change) < 100 * pirls_tolerance * abs(deviance).
    pirls_max_iter 200 dense, streamed Inner fit iteration limit. The operator route uses OperatorControl for its inner fit instead.
    history_limit 200 dense, streamed, operator Maximum length of the score history kept in optimizer_diagnostics.

    Checks at construction (messages have no trailing period):

    • outer_limit, pirls_max_iter, history_limit not a positive int: "EFS {name} must be a positive integer"
    • log_lambda_max, score_tolerance, pirls_tolerance not a real number: "EFS {name} must be a real number"; not finite: "EFS {name} must be finite"
    • "EFS score_tolerance must be nonnegative"; pirls_tolerance <= 0: "EFS pirls_tolerance must be positive"

    EFSControl(outer_limit: int = 200, log_lambda_max: float = 15.0, score_tolerance: float = 0.1, pirls_tolerance: float = 1e-07, pirls_max_iter: int = 200, history_limit: int = 200) dataclass ¶

    Limits and tolerances of the extended Fellner--Schall optimizer.

    Read by optimizer="efs" on the dense, streamed and operator routes. The numerical defaults are those of mgcv's gam.control (maxit=200, epsilon=1e-7, efs.lspmax=15, efs.tol=0.1).

    OperatorControl¶

    OperatorControl sets the limits of the operator route's coefficient fit, for fixed sp and for every refit inside the operator Fellner-Schall optimizer.

    Field Default Read by What it does
    max_modest_coefficients 64 operator Cap on the width of the small block: intercept, parametric terms and smooths other than bs="re". A wider block raises MemoryError("Modest operator width N exceeds hard cap M."). Random-effect levels are not counted.
    max_iterations 200 operator Maximum Newton iterations of the coefficient fit.
    tolerance 1e-7 operator Convergence: relative objective change below tolerance and a gradient norm within tolerance times the objective scale.
    cg_max_iterations 1000 operator Iteration limit of each conjugate-gradient solve.
    cg_rtol 1e-10 operator Relative residual tolerance of each conjugate-gradient solve.
    cg_atol 1e-12 operator Absolute residual tolerance of each conjugate-gradient solve.
    use_coarse False operator Adds a coarse correction to the preconditioner.

    Checks at construction:

    • the three integer fields not a positive integer (any numbers.Integral): "Operator {name} must be a positive integer."
    • tolerance, cg_rtol, cg_atol not finite and nonnegative: "Operator {name} must be finite and nonnegative."
    • "Operator tolerance must be strictly positive."
    • both CG tolerances zero: "Operator CG requires a positive residual tolerance."
    • use_coarse not a Python bool: "Operator use_coarse must be boolean."

    Warning

    OperatorControl accepts a NumPy integer for max_modest_coefficients, but the operator setup pass then raises ValueError("max_modest_coefficients must be a positive integer."). Pass a Python int.

    The operator Fellner-Schall optimizer attaches an error bound to a score only when tolerance <= 1e-7, cg_rtol <= 1e-10 and cg_atol <= 1e-12. The defaults sit exactly on those limits, so loosening any of them leaves every score comparison undecided. See Operator route.

    OperatorControl(max_modest_coefficients: int = 64, max_iterations: int = 200, tolerance: float = 1e-07, cg_max_iterations: int = 1000, cg_rtol: float = 1e-10, cg_atol: float = 1e-12, use_coarse: bool = False) dataclass ¶

    Explicit limits for the operator route.

    Explicit Phase-1 grid and indexed-action policy.

    prediction_policy selects, and the fitted result records, how new data are evaluated. Both policies reuse the fitted knots, constraints and transforms; neither refits a basis.

    "continuous_frozen_basis" (default) Every new value is evaluated exactly by the frozen basis, like predict.gam. Rows are independent, so results never depend on the prediction request or its batching. "mgcv_predict_bamd" Pinned predict.bamd semantics: the whole prediction request is first compressed with discrete.mf's default policy (compress.df with m=NULL: 1000/100/25 range-grid points per metric for one/two/three-plus jointly discretized variables, rounding only when a group has more unique rows than that grid), and the frozen basis is then evaluated on the compressed values. The request grid is frozen by a bounded pre-pass before any batch is evaluated or yielded, so results are invariant to prediction batch boundaries but do depend on the composition of the request, exactly as in mgcv. As in predict.bam, a model without smooth terms has no discrete prediction information and is evaluated exactly; its result then records prediction_policy="continuous_frozen_basis" and keeps the request in discretization.requested_prediction_policy. Only metric discretization changes; factor semantics are the default path's: a missing or unseen random-effect level contributes zero (100% weight on the prior, an intended divergence from mgcv's NA), a missing or unseen by level gives NaN with a warning, and a parametric factor gives NaN for a missing value and rejects unseen levels.

    max_retained_representatives bounds the per-group representative values copied into the fitted result's discretization metadata. Groups with more compact rows retain only their bounded descriptor (range, grid resolution, rounding decision and row count).

    Row sources¶

    A row source is an object that replays the training rows in batches, in the same order every time. The streamed, discretized and operator routes read their data only through one, so the full data set never has to be in one array. The how-to, including writing your own source, is in Row sources.

    All five names below come from jaxgam.data.

    RowSource¶

    RowSource is a runtime-checkable protocol. An object satisfies it when it has:

    Member What it must do
    n_rows Property: the number of rows.
    scan(batch_rows) Return an iterator of RowBatch objects, each with at most batch_rows rows, in stable positional order. Every call replays the same rows.
    fingerprint() Return a string that changes when the data change. Fits compare fingerprints to detect data changed during the fit, and raise RuntimeError.

    A source may also declare has_explicit_weights and has_explicit_offset (booleans). False says the batches hold default weights (ones) or a default offset (zeros). An attribute the source does not declare counts as supplied. On the discretized route this matters: like mgcv's bam, a supplied weight or offset column changes the seeded padding of the discretization, and so the fitted numbers.

    isinstance(obj, RowSource) checks only that the three members exist.

    Fitting routes¶

    A route is the way a fit reads its data and solves for the coefficients. FitControl.execution selects it; optimizer, sp, linear_solver and gaussian_compression select variants within a route. Every result reports the variant that ran in execution_route and how smoothing parameters were chosen in lambda_strategy.

    Route execution_route values lambda_strategy values
    Dense "dense", "gaussian_qr" "fixed", "newton_reml", "efs_reml", "lbfgs_reml"
    Streamed "stream", "stream_qr", "stream_exact_reml_qr", "stream_efs_qr", "stream_gaussian_qr", "stream_parametric_qr" "fixed", "exact_reml", "exact_reml_no_parameters", "efs_reml", "newton_reml", "lbfgs_reml"
    Discretized "discrete" "fixed", "working_model_reml"
    Operator "operator" "fixed", "efs_reml"

    On every route, check converged and convergence_info before using a fit. A fit that stops early returns a result with converged=False; it does not raise.

    Dense (default)¶

    Use it when the data fit in memory as a data frame. Requires a DataFrame or dict and linear_solver="cholesky" (the default). Returns any of the three result types; GAMResults by default.

    fit = GAM("y ~ s(x) + s(z)").fit(data)
print(fit.converged, fit.n_iter, fit.convergence_info, fit.lambda_strategy)

    True 14 full convergence newton_reml

    The setup pass builds the full model matrix and the penalty matrices in memory. The fit then selects the smoothing parameters by Newton's method on the REML criterion, refitting the coefficients by penalized iteratively reweighted least squares (PIRLS) at every trial, as mgcv's gam(method = "REML") does. For Gaussian and Gamma the log scale is also a Newton coordinate, and for NegativeBinomial(fixed=False) the log theta. The gradient and Hessian of the criterion come from automatic differentiation.

    Case What happens
    sp=None (default) Smoothing parameters selected by REML. lambda_strategy="newton_reml".
    sp=[...] Smoothing parameters held at the values given. lambda_strategy="fixed". Poisson, Binomial and fixed-theta negative binomial run one PIRLS fit (n_iter=0, convergence_info="fixed sp"). Gaussian, Gamma and estimated-theta negative binomial still run Newton steps on the scale or theta.
    No penalized terms One PIRLS fit: n_iter=0, converged=True, lambda_strategy="newton_reml".
    optimizer="efs" See Fellner-Schall optimizer.
    gaussian_compression=True See Gaussian QR compression.

    Result fields to check: converged, convergence_info ("full convergence", "step failed", "iteration limit" or "non-finite REML score or gradient", possibly followed by a note on the inner fit or a jitter), n_iter (outer iterations), lambda_strategy, execution_route.

    Limits:

    • linear_solver="qr" raises NotImplementedError("linear_solver='qr' currently requires execution='stream'."); "pcg" names execution='operator'.
    • A row source raises TypeError("A RowSource requires FitControl execution 'operator', 'stream' or 'discrete'; the dense route accepts only a DataFrame or dict.").
    • The dense fit is not memory-budgeted: the full model matrix is built whatever the result mode.
    • When the final penalized Hessian is not numerically positive definite, the fit adds a small diagonal jitter, records it in convergence_info and issues a RuntimeWarning. This happens for models with unidentifiable terms; mgcv's dropping of unidentifiable columns is not implemented.
    • A negative binomial model with estimated theta and no penalized terms keeps theta at its starting value, and fit.theta is None.

    How the dense fit works internally is in The dense fit.

    Fellner-Schall optimizer¶

    Use it when you want mgcv's extended Fellner-Schall update (gam(optimizer = "efs")) instead of Newton's method to select smoothing parameters. Requires GAM(..., optimizer="efs") with sp=None, a model with at least one penalty, and a supported family. On the streamed route also linear_solver="qr". Returns the route's usual result, with lambda_strategy="efs_reml" and an EFSOptimizerDiagnostics record in optimizer_diagnostics.

    from jaxgam import EFSControl

fit = GAM(
    "count ~ s(x) + s(z)",
    family="poisson",
    optimizer="efs",
    control=FitControl(efs=EFSControl(history_limit=8)),
).fit(data)
print(fit.converged, fit.convergence_info, fit.lambda_strategy)
print(fit.optimizer_diagnostics.stop_reason, fit.optimizer_diagnostics.outer_iterations)

    True deviance_change efs_reml
deviance_change 8

    The optimizer follows mgcv 1.9-3's efsudr. Each outer iteration refits the coefficients at trial smoothing parameters and updates their logs by the Fellner-Schall ratio. The streamed and operator routes run the same optimizer over a row source; see Streamed route and Operator route.

    Supported families on the dense route:

    Scale Families and links
    Known Poisson and Binomial with any link; negative binomial with log, identity or sqrt link, theta fixed or estimated
    Estimated Gaussian and Gamma with any link

    Anything else raises NotImplementedError. The scale is not an optimizer coordinate: each fit is scored at the incoming scale and passes its estimate to the next. For an estimated-scale family, fit.score is the criterion at the incoming scale, while fit.scale is the final fit's estimate.

    Stop reasons in convergence_info: "score_window" and "deviance_change" are converged; "iteration limit reached" (at EFSControl.outer_limit) is not.

    Limits:

    • optimizer="efs" with a fixed sp, or a model with no penalties, runs the ordinary dense fit; lambda_strategy is then "fixed" or "newton_reml" and optimizer_diagnostics is None.
    • Prior weights must lie in [1e-10, 1e10], and the penalized system must be identifiable; otherwise ValueError.
    • A fixed-theta negative binomial rejects responses strictly between 0 and 1.
    • An estimated-theta negative binomial with identity or sqrt link raises ValueError unless an offset makes every zero-coefficient mean positive (with no offset it always raises); mgcv rejects the same input.
    • With gaussian_compression=True, Fellner-Schall runs on the ordinary dense fit and execution_fallback_reason is "Gaussian QR compression requires Newton smoothing selection."
    • For a fixed-theta negative binomial, fit.theta is the fixed value under optimizer="efs" but None under the default optimizer.

    optimizer_diagnostics holds, among others, stop_reason, outer_iterations, inner_iterations, theta_iterations, accepted_score_history (at most history_limit entries) and flags for numerical events. On the streamed route it also counts the scans the optimizer made (startup_source_scans, provider_source_scans). The user guide page is Smoothing parameter selection.

    Gaussian QR compression¶

    Use it when the model is Gaussian with identity link and you want each smoothing trial to work on coefficient-sized arrays instead of the full model matrix. Requires FitControl(gaussian_compression=True) on the dense or streamed route, the exact Gaussian family with identity link, Newton selection or fixed sp, at least one penalty, an identifiable model, and prior weights in [1e-10, 1e10]. Returns the route's usual result with execution_route="gaussian_qr" (dense) or "stream_gaussian_qr" (streamed).

    fit = GAM(
    "y ~ s(x) + s(z)",
    control=FitControl(gaussian_compression=True),
).fit(data)
print(fit.execution_route, fit.execution_fallback_reason, fit.lambda_strategy)

    gaussian_qr None newton_reml

    The training rows are reduced once by a weighted QR factorization. The REML criterion and its derivatives are then computed from the small triangular factor, so the smoothing search never touches the rows again. On the dense route the model matrix is still built first; on the streamed route the reduction takes one pass over the source.

    A request that is not eligible never raises on the dense route: the ordinary fit runs and execution_fallback_reason says why.

    "count ~ s(x)",
    family="poisson",
    control=FitControl(gaussian_compression=True),
).fit(data)

    50 or fewer Newton's method, as on the dense route "newton_reml" ("fixed" with sp)

    • Above 50 penalties L-BFGS-B can make slow progress when the smoothing parameters are badly scaled against each other.     • On the streamed route a QR workspace above memory_budget_bytes raises MemoryError("Known streamed Gaussian QR workspace requires ..."); it does not fall back.
    • On the streamed route an ineligible request with sp=None and linear_solver="cholesky" raises NotImplementedError, because the fallback (exact streamed REML) needs linear_solver="qr".
    • The discretized route ignores the request and sets execution_fallback_reason to "Gaussian QR compression requires execution 'dense' or 'stream'.". The operator route ignores it without recording a reason.

    Families:

    • With linear_solver="cholesky" and fixed sp: Gaussian identity, Poisson log and Binomial logit only. (for the negative binomial: "Streamed NB observed-information fitting requires linear_solver='qr'.").
    • With linear_solver="qr": Gaussian, Poisson, Binomial and Gamma with their links, and the negative binomial with log, identity or sqrt link, theta fixed or estimated. The data must lie in the family's response and starting-value domain; Poisson with logit, probit or cloglog link is rejected because its default start leaves the link's domain.
    • Fellner-Schall: Gaussian, Binomial, Poisson, Gamma and the negative binomial (log, identity or sqrt).

    Exact REML selects the log smoothing parameters, together with the log scale for Gaussian and Gamma and the log theta for NegativeBinomial(fixed=False), by SciPy's L-BFGS-B with exact gradients. It minimizes the same REML criterion as the dense route, but by a different path, so the two agree at the optimum to numerical tolerance, not step by step. Each L-BFGS-B run is limited to steps of 5 in every log parameter (a window) and 100 iterations and 500 evaluations; a run that stops at a window edge while the score still falls opens a new window, at most 20. exact_optimizer_diagnostics reports the optimizer status, evaluation counts, the final projected gradient and the accepted score history.

    With fixed sp, an unknown-scale family (Gaussian with a non-identity link, Gamma) still optimizes the log scale, and an estimated-theta negative binomial still estimates theta; lambda_strategy stays "fixed".

    Formula limits (all NotImplementedError):

    • Smooths must be univariate s(x, bs="cr") or s(x, bs="cs"). A default s(x) (thin plate), bs="cc", bs="re", bs="gp" and multivariate smooths raise "Prepared setup currently supports only univariate cr/cs smooths."
    • te(), ti() and by= raise "Prepared setup does not yet support by-variable or tensor smooths."
    • Parametric terms must be numeric: "Prepared setup currently supports numeric parametric terms only."
    • Two smooths of the same variable: "Prepared setup does not yet support overlapping cubic terms."

    Other limits:

    • linear_solver="pcg" raises ValueError("linear_solver='pcg' requires execution='operator'.").
    • sp=None with linear_solver="cholesky" raises NotImplementedError ("Exact streamed REML requires linear_solver='qr'." or "Streamed optimizer='efs' requires linear_solver='qr'."), unless an eligible Gaussian QR request takes the fit.
    • Memory checks are prospective estimates of known arrays, not an allocator cap. Too small a budget for the setup pass raises MemoryError("Streamed setup requires at least N bytes to scan one row, ...") before any full scan. The fit check charges the requested batch_rows, not the source's row count, and raises MemoryError("Known streamed[ QR] PIRLS workspace requires ..."); lower batch_rows for a model with a few hundred coefficients. A model with a cubic smooth needs a budget above about 16 MiB, the allowance for exact knot placement.
    • Under exact REML, an inner coefficient fit that fails at any trial raises RuntimeError instead of returning converged=False.
    • No warning is issued on non-convergence; check converged.

    The setup pass compresses each group of covariates (the variables of one s() term, each te()/ti() margin, each by variable, the response and each parametric variable) to its distinct values. A group is rounded to an even grid of m points per variable only when it has more distinct rows than that grid holds, so on small data nothing is rounded. Bases are built on the compact rows, and the fit works on index tables instead of a full model matrix.

    Smoothing parameters are fixed with sp= or selected with smoothing_strategy="working_model_reml", mgcv's performance iteration (bgam.fitd): each iteration forms a working model and takes one limited Newton proposal (mgcv's Sl.fitChol) for the smoothing parameters. This is a different method from the dense route's nested REML, so the selected smoothing parameters can differ from a dense fit.

    Family Links Working model Scale
    Gaussian identity one frozen X'WX and X'Wy estimated
    Poisson log, identity, sqrt Fisher weights re-formed each iteration 1
    Binomial logit, probit, cloglog, log Fisher weights re-formed each iteration 1
    Gamma inverse, identity, log Fisher weights re-formed each iteration estimated
    Negative binomial log, identity, sqrt Newton weights re-formed each iteration; theta fixed or re-estimated each iteration by mgcv's estimate.theta 1

    Non-Gaussian fits halve a coefficient step while the penalized deviance rises, from the third iteration. An estimated negative binomial theta is updated once per iteration at the current mean; it is not optimized jointly with the smoothing parameters, and every theta evaluation is a full scan.

    Weights and offset come from the row source. As in bam, a supplied weight or offset column changes the seeded padding of short grids and so the centering constraints of the smooths. The built-in sources report has_explicit_weights=False and has_explicit_offset=False when built without them; a source that does not declare them counts as supplying both.

    Limits:

    • linear_solver other than "cholesky" raises NotImplementedError.
    • sp=None with the default smoothing_strategy raises NotImplementedError("Discrete fitting requires explicit fixed sp or opt-in smoothing_strategy='working_model_reml'.").
    • sp=None with optimizer="efs" raises NotImplementedError; with a fixed sp, optimizer has no effect.
    • Any family or link not in the table raises NotImplementedError.
    • A multi-variable random effect such as s(x, g, bs="re") raises NotImplementedError.
    • Smooths that share a variable in different groupings, such as s(x, z) + s(x), raise ValueError("continuous discretization has incompatible nesting").
    • Factors are not inferred from the dtype; list them in factor_names.
    • m smaller than a smooth's k fails with a "Basis dimension k=... exceeds number of unique data values" error, which counts compact rows.
    • The default budgets do not admit every model. A factor with many levels can exceed max_batch_bytes at the default batch_rows=65_536; the example above lowers batch_rows to 4096 for that reason. On large data a single thin-plate (tp, ts) or Gaussian-process smooth can exceed max_table_bytes; lower m, set max_knots, or raise the budget.
    • The fit's planned peak is checked against memory_budget_bytes: MemoryError("Discrete fit workspace requires N bytes, exceeding FitControl.memory_budget_bytes=M.").
    • A first proposal that leaves the family's domain raises FloatingPointError("Non-finite working-model deviance at iteration 2."), where bam also stops.
    • A rank-deficient model is not supported.

    Result fields to check: converged, convergence_info, n_iter, smoothing_strategy, working_model_proposal_evaluations, source_scans and batches_scanned (fit scans only), known_workspace_bytes, fit_peak_bytes and fit_memory_budget_bytes, prediction_policy, discretization (the grids used) and, for the negative binomial, theta. For a fixed-sp Gaussian fit, n_iter counts scale iterations and converged is always True. Reaching working_model_max_iterations gives a RuntimeWarning and converged=False.

    The user guide page is Discretized fitting; internals are in The discretized fit.

    Operator route¶

    Use it when a random effect has too many levels for a dense coefficient system. Requires FitControl(execution="operator", linear_solver="pcg"), a row source, result="prediction", fixed theta, CPU, and either a fixed sp or optimizer="efs" inside the domain described below. Returns a GAMPredictionResult with execution_route="operator".

    fit = GAM(
    "count ~ x + s(g, bs='re')",
    family="poisson",
    sp=[1.0],
    control=FitControl(execution="operator", linear_solver="pcg"),
).fit(count_source, result="prediction")

print(fit.score, fit.edf_total, fit.scale)

    A bs="re" term is held as one level index and one amplitude per row, never as dense columns, and its penalty as a scaled identity. The other terms (the "modest" block) are small dense columns, capped by OperatorControl.max_modest_coefficients. The coefficients are found by a Newton iteration whose linear systems are solved by preconditioned conjugate gradients (PCG), each matrix product being one scan of the source. The fit uses the observed curvature of the family's deviance for every family; a system that cannot be shown positive definite is refused, not switched to Fisher scoring.

    Formula scope: numeric parametric terms, s(), te() and ti() with cr, cs, cc, tp, ts or gp bases (with or without by), and s(..., bs="re"). Other bases, by= on a random effect and te()/ti() with a random effect raise NotImplementedError("Operator preparation supports numeric terms, cr/cs/cc, tp/ts/gp and re."). Factor parametric terms raise NotImplementedError("Prepared setup currently supports numeric parametric terms only."). A random effect's levels are a categorical's declared categories (unused ones included), otherwise the sorted observed values.

    Fixed sp (as in the example):

    • Supply positive finite sp, one value per penalty in formula order; a formula with no penalty needs sp=[].
    • score, edf_total and Vp are not computed (None), and scale is None for an unknown-scale family (1.0 for a known-scale family).
    • Fixed-theta negative binomial is supported: NegativeBinomial(theta, fixed=True). family="nb" (estimated theta) raises NotImplementedError("Operator fitting currently requires fixed theta.").

    Fellner-Schall (optimizer="efs", sp=None) is limited to the domain in which its score error bounds were measured:

    • Poisson with log link, else NotImplementedError("Operator EFS currently supports calibrated Poisson/log indexed fits.");
    • exactly one factor-only random effect with 257 to 4096 levels, 1 to 16 rows per level on average, batch_rows from 64 to 65536, and at most 4 other coefficients, all unpenalized (intercept and numeric parametric terms);
    • unit prior weights and a zero offset. Weights, an offset, a penalized smooth or a random slope raise NotImplementedError before the fit starts.

fit = GAM(
    "count ~ x + s(g, bs='re')",
    family="poisson",
    optimizer="efs",
    control=FitControl(
        execution="operator",
        linear_solver="pcg",
        operator=OperatorControl(tolerance=1e-11, cg_rtol=1e-13, cg_atol=1e-15),
    ),
).fit(count_source, result="prediction")

    Each Fellner-Schall decision compares two operator REML scores that carry error bounds. A trial is accepted or rejected only when the score difference exceeds the sum of the two bounds; otherwise the comparison is undecided and the fit stops with converged=False and convergence_info="indeterminate_score", keeping the last accepted state. A score gets a bound only when the responses are at most 32 and the OperatorControl tolerances are at or below their defaults, among other conditions. With the default OperatorControl, fits in this domain often stop as "indeterminate_score"; the example above uses the tighter controls that the comparison tests against mgcv use. Other stop reasons: "score_window" and "deviance_change" (converged); "iteration_limit", "inner_failure" and "invalid_update" (not converged). operator_diagnostics.efs_indeterminate_comparisons counts undecided comparisons. The bounds are empirical, measured against a high-precision reference over this domain; they are not guarantees.

    Fellner-Schall results add score, edf_total, score_error_bound and score_bound_method ("indexed_poisson_empirical_v2", "arrowhead_poisson_empirical_v2", or "unavailable" with a None bound when the accepted state had none).

    Other limits:

    • linear_solver other than "pcg" raises ValueError("execution='operator' requires linear_solver='pcg'.").
    • uncertainty other than "none" raises NotImplementedError, and predict(se_fit=True) raises RuntimeError("Prediction standard errors are not available on the operator route. ..."). Use bulk_link_variance() below.
    • A memory check that fails raises MemoryError ending "Lower batch_rows or raise the memory budget.". The fit plans for batch_rows rows per batch, or for the source's row count when that is smaller.
    • sp=None without optimizer="efs" raises NotImplementedError("Operator fitting requires explicit fixed sp.").
    • device other than None or "cpu" raises NotImplementedError.
    • A system without a positive-definiteness certificate raises LinAlgError out of fit(); some positive-definite systems are refused. A PCG failure or the iteration limit returns converged=False.
    • Every scan re-hashes every row of the source to prove the replay is identical.

    Result fields to check: converged, convergence_info, n_iter (Newton iterations for fixed sp, outer iterations for Fellner-Schall), source_scans and batches_scanned (fit work; setup scans are in operator_diagnostics.preparation_started_scans), known_workspace_bytes (None for fixed sp), and operator_diagnostics (Krylov iterations, solves, the final gradient norm). On Fellner-Schall results operator_diagnostics describes the accepted refit only, while source_scans covers the whole run.

    bulk_link_variance(training_source, calibration_data, *, probes, seed, memory_budget_bytes, control=None, scale=None, max_calibration_standard_errors=5.0) rebuilds the Fisher system at the fitted coefficients from the original training source (its fingerprint and row count must match the fit), solves it for probes random right-hand sides (at least 2), and keeps a probes-by-coefficients sketch. estimator.estimate_iter(source) then yields batches with positions, variance, monte_carlo_se and link_se, on the link scale only.

    The rows of calibration_data (at least 1, at most min(256, batch_rows)) are also solved exactly. Each estimate times probes, divided by the exact variance, should follow a chi-square distribution with probes degrees of freedom; the call converts that to an equivalent normal deviate (calibration.equivalent_deviates) and raises RuntimeError when any exceeds max_calibration_standard_errors (default 5, a two-sided level of 5.7e-7 per row). The Monte Carlo standard error describes sampling variation only, not bias of the iterative solves, and calibration on the selected rows is not a guarantee for other rows. An unknown-scale family needs scale=. control is a PCGControl from jaxgam.execution.operator.system (default relative tolerance 1e-10), independent of FitControl.operator. The method raises RuntimeError on a result from another route or one that did not converge.

    Formula syntax¶

    Formulas follow R's notation for mgcv::gam:

    formulas = [
    "y ~ s(x)",                     # one smooth (thin plate)
    "y ~ s(x) + z",                 # a smooth plus a numeric parametric term
    "y ~ te(x, z, k=5)",            # tensor product
    "y ~ s(x) + s(z) + ti(x, z)",   # main effects plus tensor interaction
    "y ~ s(x, z, bs='gp', k=30)",   # Gaussian process smooth
    "y ~ s(x, by=f) + f",           # factor-by smooth
    "y ~ s(x) + s(g, bs='re')",     # random intercept
    "y ~ 0 + s(x)",                 # no intercept
]
for formula in formulas:
    print(formula, GAM(formula).fit(data).converged)

    What the parser accepts:

    • Calls s(), te() and ti() only. Terms join with +. 0 +, - 1 or -1 drops the intercept. A bare name is a parametric term: a numeric column enters as is, a factor column (pandas categorical or string) with treatment contrasts, an ordered factor with polynomial contrasts.
    • Positional arguments of a smooth must be variable names.
    • k must be an integer literal and bs a string literal, so per-margin lists such as te(x, z, k=[5, 6]) raise ValueError.

    What it rejects:

    Input Error
    x1*x2 ValueError("Unsupported operator in formula: Mult. Only '+' and '-' are supported. ...")
    x1:x2 ValueError("Cannot parse formula RHS as an expression: ...")
    I(x), offset(o), factor(g), t2(x, z) ValueError("Unknown function 'I()' in formula. Supported: ['s', 'te', 'ti']")
    s(log(x)) ValueError("Positional arguments to s() must be variable names. ...")
    s(x, fx=True) NotImplementedError (fixed-df unpenalized splines are not supported)
    s(x, sp=1) NotImplementedError; use GAM(sp=[...]) instead
    s(x, id=1) NotImplementedError (linked smoothing parameters are not supported)
    s(x, bs="ps") and any other unregistered basis KeyError("Unknown basis type: 'ps'. Available: ...") when the fit runs

    Other keyword arguments inside a smooth are evaluated as literals and passed to the smooth; keywords that no smooth reads (for example pc=) are silently ignored. Use the offset argument of fit() (dense route) or of the row source for an offset.
