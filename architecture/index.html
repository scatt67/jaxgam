    Architecture overview¶

    Scope¶

    This page is the entry point to the maintainer documentation. It says what JaxGAM does, how the three phases split the code, which sub-package depends on which, which fitting routes exist and how one is selected, and defines the terms the other architecture pages use. It ends with a reading order.

    JaxGAM is a Python port of R's mgcv. It fits generalized additive models: a response from an exponential family (Gaussian, Binomial, Poisson, Gamma, or negative binomial) whose link-scale mean is a sum of parametric terms and penalized smooth functions (thin plate, cubic, Gaussian process, random effect and tensor product bases). Smoothing parameters are chosen by REML or by an extended Fellner-Schall iteration, or fixed by the caller. The public entry is GAM in jaxgam/api.py: GAM(formula, family, ...).fit(data, ...) returns a frozen result object that predicts, and on the default route also summarises and plots. Besides the in-memory (dense) route, the package fits from a replayable row source by streaming, by a discretized compact design (the analogue of bam(discrete=TRUE) in mgcv's R/bam.r), and by a matrix-free operator route for random effects with very many levels.

    jaxgam/summary/ Phase 3. summary, GAMSummary, Davies' method for weighted chi-square tails.
    jaxgam/plot/ Phase 3. plot_gam (matplotlib).

    Layout by route¶

    jaxgam/formula/, jaxgam/fitting/ and jaxgam/execution/ are laid out the same way. A module that only one route uses is in that route's sub-package, and the sub-package has the same name in each of the three packages. A module that the dense fit uses, or that more than one route uses, stays at the top level of its package.

    Several file names occur in more than one place: for example jaxgam/fitting/reml.py (the dense criterion), jaxgam/fitting/stream/reml.py and jaxgam/execution/stream/reml.py, or jaxgam/formula/prepare.py and jaxgam/formula/operator/prepare.py. The package path tells them apart, so these pages always write the full path. A sub-package's initializer, such as jaxgam/execution/operator/__init__.py, holds a description and imports nothing, so importing one module of a route does not load the rest. The other packages (data/, smooths/, penalties/, families/, links/, inference/, summary/, plot/) are flat, and so are the test directories: the tests of jaxgam/execution/operator/fit.py are in tests/test_execution/test_operator_fit.py.

    How it works¶

    The three phases¶

    Every fit passes through three phases.

    • Phase 1, setup (NumPy, CPU). Parse the formula, build bases, penalties and identifiability constraints, and either assemble the dense model matrix (ModelSetup.build in jaxgam/formula/design.py) or prepare observation-independent metadata by scanning a row source (prepare_model in jaxgam/formula/prepare.py, build_continuous_discrete_setup in jaxgam/formula/discrete/continuous_setup.py, prepare_operator_model in jaxgam/formula/operator/prepare.py). Packages: data, formula, smooths, penalties.
    • Phase 2, fit (JAX). Arrays cross to a JAX device and the smoothing parameters and coefficients are estimated. JIT kernels live in jaxgam/fitting/; host-side drivers that iterate over row sources, hold accepted and trial states and enforce memory budgets live in jaxgam/execution/. Not all of fitting/ is jitted: the outer loop of NewtonOptimizer.run in jaxgam/fitting/newton.py is host Python, and jaxgam/fitting/stable_log_det.py runs in NumPy between jitted evaluations.
    • Phase 3, post-estimation (NumPy, CPU). Results return through to_numpy and become frozen result objects (jaxgam/results.py) holding a prediction core (jaxgam/inference/); summary and plot work on the full result only.

    Directions that never occur:

    • No Phase 1 package (data, formula, smooths, penalties) imports fitting, execution, families, links, jax_utils, inference, results, summary, plot or api. Family objects reach Phase 1 code as arguments, without an import.
    • families and links import no Phase 1, Phase 2 or Phase 3 package.

    • inference never imports fitting or execution.

    The one known exception to "kernels do not depend on drivers" is in jaxgam/fitting/data.py: _structural_penalty_roots imports structural_rank from jaxgam/execution/qr.py inside the function, with a comment giving the circular import as the reason.     Rules and invariants¶

    • Phase 1 stays free of JAX. data, formula, smooths and penalties must not import jax, jaxgam.fitting, jaxgam.execution, jaxgam.families, jaxgam.links or jaxgam.jax_utils. Six tests load a Phase 1 module under a stub jaxgam package and assert that no jax module was imported: test_discretize_module_imports_without_jax (tests/test_data/test_discretize.py) and its siblings in tests/test_data/test_continuous_discretize.py, tests/test_data/test_continuous_frame.py, tests/test_data/test_continuous_request.py, tests/test_formula/test_continuous_metadata.py and tests/test_formula/test_rank_coordinates.py. No other import-boundary check (such as an import linter) runs in CI; the rest of this page's direction rules are kept by review.
    • Kernels do not import drivers. fitting/ imports execution/ only in _structural_penalty_roots. A new import in that direction is likely to create a circular import, because jaxgam/execution/ imports streamed routes that import jaxgam/fitting/data.py.
    • Float64 everywhere. jaxgam/__init__.py sets jax_enable_x64 before anything is compiled. See Numerics and platform.
    • Row-source routes return prediction results only. _fit_stream, _fit_discrete and _fit_operator raise NotImplementedError for result="full" or "inference", and take weights and offset from the source, never from fit(weights=, offset=).
    • Phase 3 operates on host arrays. Result builders convert with to_numpy before any covariance, EDF or prediction work.

    Pitfalls¶

    • A plain import jaxgam.smooths.tprs imports JAX through jaxgam/__init__.py. Checking "no JAX in Phase 1" by importing a module in a normal interpreter proves nothing; use the stub-package pattern of the guard tests.
    • jaxgam/execution/__init__.py says execution code "does not construct formula bases or perform post-estimation work". The discretized route's driver calls Phase 1 setup builders, and bulk_link_variance runs after the fit, so treat that sentence as a guideline, not a fact about every module.
    • GAM does not validate family, sp or the formula at construction: an unknown family name raises KeyError only in fit, from Registry.get_class.
    • FitControl.smoothing_strategy defaults to "exact_reml" and is read only by the discretized route, which cannot use that default without an sp.

    Where to change things¶

    To do this Edit
    Add a public name jaxgam/__init__.py (__all__)
    Add a fit argument or control field jaxgam/control.py and its readers in jaxgam/api.py; see Lifecycle of a fit
    Change route selection GAM.fit and the _fit_* methods in jaxgam/api.py
    Add a family, link or smooth see Extension points
    Change what a result keeps jaxgam/results.py, jaxgam/inference/predictor.py; see Phase 3
    Change the Phase 1 to 2 transfer to_jax in jaxgam/jax_utils.py, FittingData.from_setup in jaxgam/fitting/data.py
    Add a module to a route That route's sub-package in jaxgam/formula/, jaxgam/fitting/ or jaxgam/execution/. Put it at the top level of the package instead when the dense fit or a second route uses it; see Layout by route.

    A planned refactor will merge the per-route controllers in fitting/ and execution/ and the routing in jaxgam/api.py; see the unified fitting design.

    Glossary¶

    • Smoothing parameter. The weight lambda_j on penalty S_j. GAM(sp=) takes natural-scale values; the code optimizes log_lambda. Results report a supplied sp verbatim (_report_smoothing_params in jaxgam/results.py) and estimated ones as exp(log_lambda).
    • Penalty, S_lambda. The penalty matrix sum_j lambda_j S_j, held as local coefficient-block descriptors in PenaltyStructure (jaxgam/penalties/structure.py) and materialized by FittingData.S_lambda.
    • Scale. The dispersion phi; 1 for known-scale families (scale_known), estimated for Gaussian and Gamma.
    • Theta. The negative binomial shape parameter, fixed or estimated (NegativeBinomial(theta, fixed=...) in jaxgam/families/negative_binomial.py).
    • EDF. Effective degrees of freedom: the trace of F = (X'WX + S_lambda)^-1 X'WX over a smooth's coefficient block. edf1 is 2 edf - tr(F F) per block, which summary uses to set the reference degrees of freedom of the smooth tests (_compute_per_smooth_edf, _compute_per_smooth_edf1 in jaxgam/results.py).
    • PIRLS. Penalized iteratively reweighted least squares, the inner coefficient fit at fixed smoothing parameters: pirls_loop (jaxgam/fitting/pirls.py) and source_pirls (jaxgam/fitting/source_pirls.py, the port of gam.fit3 in mgcv's R/gam.fit3.r and gam.fit4 in R/gam.fit4.r).
    • REML. Restricted maximum likelihood, the smoothing-selection criterion (REMLCriterion in jaxgam/fitting/reml.py). method="REML" is the only accepted method; "ML" raises NotImplementedError.
    • Newton optimizer. The dense outer loop over log smoothing parameters, newton_optimize and NewtonOptimizer in jaxgam/fitting/newton.py, a port of newton in mgcv's R/gam.fit3.r.
    • Fellner-Schall (EFS). The extended Fellner-Schall update of smoothing parameters, selected by optimizer="efs", a port of efsudr in mgcv's R/gam.fit4.r. Dense in jaxgam/execution/efs.py, streamed in jaxgam/execution/stream/efs.py, operator in jaxgam/execution/operator/efs_controller.py; settings in EFSControl.
    • Row source. An object satisfying the RowSource protocol (jaxgam/data/source.py): n_rows, scan(batch_rows) yielding RowBatch objects in a stable order, and fingerprint(). Built-ins: ArrayRowSource, DataFrameRowSource, MemmapRowSource.
    • Scan. One full pass over a row source in batches of batch_rows rows. Results count fit scans in source_scans and batches_scanned.
    • Fingerprint. A content digest of a row source, compared at the start and end of a fit (single_fit_fingerprints) to detect data that changed.
    • Compact or discretized design. On the discrete route, the compact frame of representative covariate rows (build_compact_setup_frame in jaxgam/data/continuous_frame.py) plus row selectors, and the indexed design built on it (FrozenDiscreteDesign, DeviceDiscreteDesign), on which kernels such as discrete_xwxd act. The analogue of mgcv's discrete.mf and XWXd.
    • Working model. On the discrete route, the frozen coefficient-space Gaussian problem on which one Sl.fitChol proposal (mgcv R/fast-REML.r) is taken per iteration; repeated re-forming of it is the performance iteration of bgam.fitd (R/bam.r). Selected by smoothing_strategy="working_model_reml".
    • Prediction policy. On the discrete route, continuous_frozen_basis evaluates new covariate values exactly; mgcv_predict_bamd first compresses the whole request as mgcv's predict.bamd does.
    • CoefficientMap. The Phase 1 to 3 contract in jaxgam/smooths/constraints.py: per-term TermBlock entries holding the identifiability transform (Z_centering, del_index) that maps a raw basis block to the constrained coefficients (transform_X).
    • PredictSpec. The observation-free prediction state (CoefficientMap, factor levels, smooth metadata) in jaxgam/formula/predict_matrix.py.
    • Operator route. The matrix-free route for large random effects: indexed random effects (IndexedRandomEffect) never form dense columns, a small "modest" block holds the other terms, and systems are solved by preconditioned conjugate gradients (jaxgam/fitting/operator/iterative.py).
    • Gaussian QR compression. FitControl(gaussian_compression=True): one weighted QR reduction of a Gaussian identity model, then coefficient-space smoothing trials (jaxgam/execution/gaussian_qr/preparation.py).
    • Fisher factor. A retained triangular factor of the penalized Fisher information (lower Cholesky, or a PivotedQRFisherFactor) from which prediction standard errors are computed without a dense covariance.
    • Execution route. The execution_route string on every result, naming the sub-route that ran; lambda_strategy names how smoothing parameters were set; execution_fallback_reason records an unmet Gaussian QR request.
    • Host driver and kernel. A driver is Python in jaxgam/execution/ that loops, scans and decides; a kernel is a pure function in jaxgam/fitting/, usually jitted.
    • Memory budget. FitControl.memory_budget_bytes and output_budget_bytes: prospective estimates of known arrays, checked before allocation and raising MemoryError. Dense fitting is not budgeted.

    Reading order¶

    1. Lifecycle of a fit - one GAM.fit() call end to end: checks, routing, the _fit_* methods, route labels.
    2. Phase 1: setup - formula parsing, smooth construction, CoefficientMap, penalties, and the streamed, discretized and operator setup.
    3. Data sources - RowSource, RowBatch, built-in sources, fingerprints and discretization.
    4. Phase 2: dense fitting - FittingData, PIRLS, the REML criterion, the Newton optimizer, dense EFS and Gaussian QR.
    5. Phase 2: streamed fitting - streamed PIRLS, QR reducers, exact streamed REML, streamed theta and EFS.
    6. Phase 2: discretized fitting - indexed design actions, the working-model REML proposal and the performance iteration.
    7. Phase 2: operator fitting - matrix-free actions, PCG, the operator EFS controller and bulk variance.
    8. Phase 3: results and prediction - result types, the prediction core, batched prediction, summary, plot and pickling.
    9. Extension points - family, link and smooth base classes, registries, and checklists for adding one.
    10. Testing and CI - test layout, the R bridge, tolerance classes, the validation matrix and CI jobs.
    11. Numerics and platform - float64, the pinned LAPACK provider, BLAS threads, the Accelerate guard, determinism.
